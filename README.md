# Посредник — выгрузка контекста конфигурации 1С для LLM

Инструмент-связка из двух частей: внешняя обработка для 1С:Предприятие 8.3, которая разбирает выгруженную в файлы конфигурацию, и системный промпт для LLM, который умеет с этой обработкой разговаривать. Цель — давать языковой модели **ровно тот** кусок исходников, который она в данный момент просит, а не вываливать всю конфигурацию разом.

## Что в репозитории

| Файл | Назначение |
|---|---|
| `Посредник.epf` | Внешняя обработка 1С (v1) |
| `1C_INSTRUCTIONS.md` | Системный промпт для LLM под v1 |
| `TS4V2.md` | ТЗ на следующую версию (v2) — см. ниже |
| `README.md` | Этот файл |

## Зачем это нужно

LLM хорошо помогает с 1С, но только если видит реальный код, а не его свои фантазии о том, как «обычно» называются методы общих модулей. Полная конфигурация в контекст не лезет — десятки мегабайт. Решение: модель присылает короткий запрос вида «дай мне модуль X и структуру справочника Y», человек прогоняет запрос через обработку, обработка собирает результат в `_CONTEXT.md`, человек вставляет результат в чат. Дальше — продолжение разговора с уже точным знанием.

## Версия v1 (то, что лежит в репе сейчас)

### Что умеет

- Принимает запросы двух типов:
  - **`SCHEMA:Тип.Имя`** — структура объекта (реквизиты, табличные части, формы — на уровне метаданных XML).
  - **`FETCH:Тип.Имя.модуль`** — теоретически отдача исходников модулей.
- Опирается на файл `CONFIG_MAP.md` — карту конфигурации, которую человек должен сгенерировать заранее.
- Парсит корневые `.xml` объектов и формирует markdown-карту реквизитов.

### Что НЕ умеет (известные ограничения v1)

- **Не видит модули и формы.** Парсятся только `.xml` метаданных. Папки `Ext/` и `Forms/` с реальными `.bsl`-файлами не обходятся — то есть `FETCH` фактически отдаёт пусто.
- **Теряет составные типы.** XML читается построчно через `ЧтениеXML`, без захода в `Type/QualifierName`, поэтому `СправочникСсылка.X` или `Строка(150)` не различаются.
- **Не понимает табличные части.** Все реквизиты валятся в один плоский список — связь «таб.часть → её реквизиты» теряется.
- **Нет графа зависимостей** и поиска по коду.
- **Нет режима «дай всё» (`BUNDLE`)** — для онбординга нового чата приходится таскать руками.

### Сборка и использование v1

1. Открой `Посредник.epf` в режиме 1С:Предприятие поверх любой ИБ.
2. Укажи путь к корню выгрузки (там, где лежит `Configuration.xml`).
3. В поле запроса введи команду из инструкции и нажми «Выполнить» — результат пишется в `_CONTEXT.md`.
4. Вставь содержимое `_CONTEXT.md` в чат с LLM.

Полный протокол команд, правила работы и шпаргалка — в `1C_INSTRUCTIONS.md`. Этот файл целиком копируется в Project Instructions Claude или в Custom Instructions ChatGPT.

### Установка инструкции в LLM

**Claude** — Settings → Projects → создай или открой проект → Instructions → вставь содержимое `1C_INSTRUCTIONS.md`.

**ChatGPT** — настройки → Custom Instructions → второе поле («How would you like ChatGPT to respond»). Или просто первым сообщением нового чата.

**Любой другой** — в системный промпт.

После этого модель будет выдавать команды формата `FETCH:...` и `SCHEMA:...`, и ждать от тебя содержимое `_CONTEXT.md` в ответ.

## Версия v2 — в работе

В файле **`TS4V2.md`** лежит подробное техническое задание на следующую версию. Главное, что закроет v2:

- **Чтение модулей и форм** — основной баг v1, из-за которого `FETCH` не работает.
- **`ПостроительDOM` вместо построчного XML** — фикс составных типов, длин строк и табличных частей.
- **Новые команды:**
  - `GREP` — полнотекстовый поиск по `.bsl` с контекстом.
  - `DEPS` — граф зависимостей (кто кого вызывает).
  - `BUNDLE` — снимок всей конфы одним файлом для длинного контекста.
- **Кириллические пути, UNC, Linux** — отдельные тест-кейсы.

ТЗ содержит контекст и список багов v1, полную сетку команд с примерами, архитектуру и структуры данных, EBNF-грамматику протокола, тест-кейсы T1–T15 на функциональность, B1-T…B8-T на регрессию багов, E1–E6 на ошибки, и поэтапный план разработки M1–M9. Полный объём — 747 строк.

Реализация v2 ещё не сделана. Когда будет готова — этот README обновится.

## Стек и требования

- 1С:Предприятие 8.3 (управляемые формы)
- Платформа `8.3.14+` для v2 (для v1 — `8.3.10+`)
- Windows или Linux
- Никаких внешних компонент, COM, ADODB — только встроенный язык
