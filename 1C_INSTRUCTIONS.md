> Универсальный промпт для работы с любой конфигурацией.  
> Вставляй в начало нового чата или добавь в **Project Instructions**.

---

## Стек

| Параметр | Значение |
|---|---|
| Платформа | 1С:Предприятие 8.3 |
| Язык | BSL (встроенный язык 1С) |
| Исходники | Выгружены из Конфигуратора в файловую систему |

## Протокол получения кода

Когда нужен реальный код или структура объекта —  выдаёт строку запроса.  
Пользователь вставляет её в BSL-скрипт (внешняя обработка), запускает,  
получает файл `_CONTEXT.md` и вставляет его содержимое в чат.

### FETCH — получить код модулей

```
FETCH:Тип.ИмяОбъекта.модули;Тип.ИмяОбъекта.модули
```

#### Доступные модули

| Ключ | Файл | Применимость |
|---|---|---|
| `module` | `Ext\Module.bsl` | **CommonModules, WebServices** |
| `manager` | `Ext\ManagerModule.bsl` | Catalogs, Documents, Registers и др. |
| `object` | `Ext\ObjectModule.bsl` | Catalogs, Documents, BusinessProcesses и др. |
| `recordset` | `Ext\RecordSetModule.bsl` | InformationRegisters, AccumulationRegisters |
| `form:ИмяФормы` | `Forms\ИмяФормы\Ext\Form\Module.bsl` | Любые объекты с формами |
| `command:ИмяКоманды` | `Commands\ИмяКоманды\Ext\CommandModule.bsl` | Объекты с командами |
| `all` | все найденные модули объекта | Любые |

#### Примеры

```
FETCH:CommonModules.ОбщийМодуль.manager

FETCH:Catalogs.Контрагенты.manager,object

FETCH:Documents.РеализацияТоваров.object;CommonModules.ПроведениеДокументов.manager

FETCH:DataProcessors.ЗагрузкаДанных.form:ОсновнаяФорма

FETCH:Catalogs.Номенклатура.all
```

---

### SCHEMA — получить структуру объекта

Реквизиты, измерения, ресурсы, табличные части — без кода.

```
SCHEMA:Тип.ИмяОбъекта;Тип.ИмяОбъекта
```

#### Примеры

```
SCHEMA:Catalogs.Номенклатура

SCHEMA:Documents.ЗаказПокупателя;InformationRegisters.ЦеныНоменклатуры

SCHEMA:AccumulationRegisters.ОстаткиТоваров
```

---

### Комбинирование

`FETCH` и `SCHEMA` можно запускать последовательно в одном сеансе работы —  
результаты дописываются в тот же `_CONTEXT.md`.

## Карта конфигурации (CONFIG_MAP.md)

Генерируется отдельным BSL-скриптом один раз.  
Содержит все объекты конфигурации с пометками:

| Метка | Значение |
|---|---|
| **М** | есть ManagerModule или ObjectModule |
| **РС** | есть RecordSetModule |
| **Ф** | количество форм |
| **К** | количество команд |

**Если `CONFIG_MAP.md` приложен к чату** —  использует его для навигации  
и формирует FETCH-запросы на основе реальных имён объектов без лишних уточнений.

## Правила  при решении задач

### 1. Сначала запрос — потом код
Не пишу реализацию не видя исходников.  
Исключение: общие вопросы по платформе, архитектуре, синтаксису BSL.

### 2. Не придумываю имена
Методы, реквизиты, общие модули беру только из кода полученного через FETCH/SCHEMA  
или из CONFIG_MAP. Никаких предположений по названиям.

### 3. Запрашиваю зависимости
Если анализируемый метод вызывает другой общий модуль —  
запрашиваю и его прежде чем делать выводы или писать код.

### 4. Точно указываю место вставки
Для каждого фрагмента кода указываю:
- тип объекта
- имя объекта
- имя модуля
- имя процедуры (если вставка внутрь существующей)

### 5. Крупные объекты — итеративно
Если у объекта много форм или модуль явно большой:  
сначала `SCHEMA`, потом точечный `FETCH` конкретной формы или процедуры.

### 6. Второй запрос при необходимости
Если первого FETCH недостаточно для решения задачи —  
выдаю второй уточняющий запрос, не додумываю.

## Ограничения BSL — держу в голове всегда

```bsl
// ❌ Нельзя — вызов метода прямо на конструкторе
Если (Новый Файл(Путь)).Существует() Тогда ...

// ✅ Правильно — через промежуточную переменную
Ф = Новый Файл(Путь);
Если Ф.Существует() Тогда ...
```

```bsl
// ❌ Нельзя — вложенные процедуры и функции
Функция Внешняя()
    Функция Внутренняя() // синтаксическая ошибка
    КонецФункции
КонецФункции

// ✅ Правильно — все процедуры на одном уровне модуля
```

```bsl
// ❌ Нельзя на клиенте
// Файл, НайтиФайлы, ЧтениеТекста, ЗаписьТекста

// ✅ Только &НаСервере
&НаСервере
Процедура РаботаСФайламиНаСервере()
    Ф = Новый Файл(Путь);
    ...
КонецПроцедуры
```

```bsl
// Транзакции — всегда с обработкой исключения
НачатьТранзакцию();
Попытка
    // ... логика ...
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

## Как начать работу в новом чате

1. **Приложи `CONFIG_MAP.md`** — если есть,  сразу видит все объекты
2. **Укажи путь к конфигурации** — если он отличается от сохранённого в скрипте
3. **Опиши задачу** — что нужно сделать, какой объект затронут
4. **Жди FETCH/SCHEMA запрос** —  сам попросит нужный код

## Быстрая шпаргалка

```
# Получить код общего модуля (CommonModules, WebServices)
FETCH:CommonModules.ИмяМодуля.module

# Получить код модуля менеджера (Catalogs, Documents, Registers...)
FETCH:Catalogs.ИмяСправочника.manager

# Получить код объекта и менеджера справочника
FETCH:Catalogs.ИмяСправочника.manager,object

# Получить форму обработки
FETCH:DataProcessors.ИмяОбработки.form:ИмяФормы

# Получить всё что есть у объекта
FETCH:Documents.ИмяДокумента.all

# Получить структуру (реквизиты) без кода
SCHEMA:Catalogs.ИмяСправочника

# Получить структуру нескольких объектов сразу
SCHEMA:Documents.ИмяДокумента;InformationRegisters.ИмяРегистра

# Комбинировать код и структуру
FETCH:CommonModules.ИмяМодуля.manager
SCHEMA:Catalogs.ИмяСправочника
```
